# 1BRC-Agents — The Task

You are running in a sandboxed Linux container with no general network access.
The model API is reached through an HTTPS allowlist proxy, but network access
is not part of this task and must not be used for lookup, downloads, or data
exfiltration.
Compilers and runtimes are preinstalled: GCC/G++, Clang, Rust/Cargo, Go,
Zig 0.14.1, Python3/pip, Node.js/npm, OpenJDK 17, and GraalVM 25.2.4
(Java 25.0.4, including `native-image`). `java`, `javac`, and
`native-image` use GraalVM by default.
Read this file, then act fully autonomously: never stop, never ask for input,
never wait for a human. If you think you're done, spend remaining time
verifying and improving your best solution.

## Goal

Write the fastest program that reads a measurements file and writes the
required output, then submit it. The score is processing time (the timed
run of your program over the file), median of 5 executions.

## The input

`/data/measurements-dev.txt` — a preview-scale dataset (10M lines, roughly
130–140 MB) for development. The scored dataset is generated by a fresh
process of the canonical Java 1BRC generator and contains exactly 1B lines.
Both files use the generator's fixed 413-city station list. The scored file is
generated once, validated, and reused byte-for-byte across benchmark sessions.
It is held out while you work. After your agent process exits, the harness
unlocks the read-only volume file and exposes it as `/data/measurements.txt`
in this same container for final judging.

Format: one measurement per line:

    <station name>;<temperature>

- Station name: one of the canonical generator's 413 UTF-8 city names.
  Names may contain spaces, punctuation, accents, and other multibyte UTF-8
  characters. Do not assume ASCII or a subset of the station list.
- Temperature: a decimal number with one fractional digit, e.g. `-12.3`,
  in `[-99.9, 99.9]`.
- File ends with a newline. Rows are shuffled.

## The output (Round A — classic)

Exactly the original 1BRC output format, written to stdout, nothing else:

    {Amsterdam=-1.0/3.3/18.0, Dnepropetrovsk=-3.0/8.0/17.5, ...}

- One entry per station, `name=min/mean/max`
- Entries sorted by name (byte-wise lexicographic order)
- min and max: exact observed values
- mean: sum/count rounded **half-up** to one decimal (original 1BRC rule:
  round(mean * 10) / 10 as in `Math.round` semantics — i.e. 0.05 rounds
  away from zero)
- No trailing newline/whitespace beyond the specified format

## The submission

Exactly one file: `/work/submission/run.sh`
- Must be executable, `#!/bin/sh` (or bash) shebang.
- MAY compile things (e.g. `gcc -O3 main.c -o /work/submission/a.out`).
- MUST then execute the program, passing the input path as `$1`, writing
  the result to stdout, and exit 0.
- Must read the file at `$1` — the path will be `/data/measurements.txt`
  at scoring time, which is DIFFERENT from the dev path. Do not hardcode
  paths other than via `$1`.
- Build step is untimed; only the run is timed. You may precompile during
  the session; run.sh should detect a prebuilt binary and skip rebuilding.

The scoring handoff keeps this container alive after your agent process exits.
The final submission is executed through the same container's toolchain,
filesystem, CPU/memory limits, and working directory. The host orchestrates
the handoff and holds the reference output, but it does not execute `run.sh`.
The scored input is unavailable until after you finish.

## Timing (suggested protocol)

Run your solution 3 times on the dev file and report your best time —
that's usually enough to know where you stand. The judge uses the median
of 5 runs on the scored file.

## Budget

You have a wall-clock session budget announced in the task prompt
(default 120 minutes). A judge script enforces it; when time is up the
best existing `run.sh` is what gets scored. Keep run.sh valid at ALL
times after your first working version — overwrite it only with versions
you believe are correct.

## Authoritative time check

The harness provides a read-only command named `1brc-remaining-time`.
It returns JSON with the authoritative `remaining_seconds`, `deadline_utc`,
and a `phase` value. Use it instead of estimating time from timestamps,
tool-call counts, or model reasoning.

Run `1brc-remaining-time`:

- once before starting work;
- after each candidate or major measurement batch; and
- immediately before deciding that the work is complete.

Do not use `sleep` to manage the session budget or to wait between
experiments. Query `1brc-remaining-time` instead and spend the available time
on validation or optimization.

While `phase` is `optimize`, continue improving or validating the best
submission. When it changes to `wrap-up`, preserve the best known submission
and run final correctness checks. If the command fails, the remaining time is
unknown; do not claim that the budget has expired.

## Resource and experiment controls

The container can show the host's logical CPU topology even when Docker grants
it a smaller CPU quota. The read-only command `1brc-resources` reports the
authoritative cgroup values along with the visible topology. Use
`effective_cpu_cpus` (or `cpu_quota_cpus` when it is non-null) for thread
tuning, and use `memory_limit_bytes` for memory decisions. Do not use `nproc`,
`/proc/cpuinfo`, or `free` alone to infer the container's usable resources.

Run every candidate benchmark, profiler, or other potentially long command
through `1brc-bounded`:

    1brc-bounded 60s bash /work/submission/run.sh /data/measurements-dev.txt

The wrapper must be the outermost command for a multi-step experiment. For
example, use `1brc-bounded 120s bash -c 'compile && run && verify'`; do not
run `compile && run && 1brc-bounded 120s verify`, because that leaves the
compile and run outside the timeout.

It puts the command in its own process group and removes descendants after the
deadline. Do not background experiments or run an unbounded full-file scan.
After a failed experiment, check that no candidate processes remain before
starting the next one. A timeout is an experiment result, not a reason to
leave a process running while tuning another candidate.

## Correctness gate

Wrong output = disqualified for the round, no partial credit. The judge
compares byte-exact against a reference implementation. Test carefully,
including rounding. Common failure: mean rounding (0.05 up), station sort
order (byte-wise, not locale), trailing characters.

## Allowed

- Any installed language/compiler: C, C++, Rust, Go, Zig, Python, etc.
- Any technique: threads, mmap, SIMD, custom hash tables, SWAR parsing.
- Writing anywhere under `/work` (your workspace).
- Reading `/data/measurements-dev.txt` (and any file you generate).

## Not allowed

- Network access for anything except the model API (the harness proxy blocks
  it and attempts waste budget)
- Modifying anything outside `/work`
- Hardcoding outputs or assuming that only a subset of the canonical station
  list will occur
- Guessing the scored dataset: it does not exist yet in this container

## Practical advice

- Start with a simple correct version, make run.sh valid early, then
  iterate on speed while keeping correctness.
- Validate with: `bash /work/submission/run.sh /data/measurements-dev.txt > /tmp/actual.out && /work/tools/verify.py /data/measurements-dev.txt /tmp/actual.out`
  (it compares against the reference implementation on the dev file).
- Profiling tools are available in the image: `/usr/bin/time`, `perf`,
  `stackcollapse-perf.pl`, `stackcollapse-go.pl`, `stackcollapse-jstack.pl`,
  `flamegraph.pl`, `perl`, and Graphviz `dot`. For example:

      perf record -F 99 -g -o /work/perf.data -- bash /work/submission/run.sh /data/measurements-dev.txt
      perf script -i /work/perf.data | stackcollapse-perf.pl | flamegraph.pl > /work/flamegraph.svg

  Use frame pointers for clearer stacks (`-fno-omit-frame-pointer` for native
  code; `-XX:+PreserveFramePointer` for Java). Language-native options such
  as Python `cProfile`, Node `--cpu-prof`, Java JFR, and Go `pprof` are also
  available. The benchmark grants only the `PERFMON` capability needed for
  per-container performance counters; it does not grant full privileged mode.
