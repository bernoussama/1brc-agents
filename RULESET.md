# 1BRC-Agents — Ruleset v1 (draft)

**Benchmark:** frontier AI models compete head-to-head writing the fastest program for a 1BRC-style task, fully autonomously, from a cold start.

**What it measures (say it out loud, honestly):** retrieval + adaptation + execution. Every 1BRC trick is in the training data. The test is whether an agent can *assemble, verify, and iterate* on those ideas against a live profiler without a human in the loop — the Prime Intellect finding: all models find the same ideas, the gap is experimental discipline. That's what we're measuring.

**What it does NOT measure:** novel algorithm invention. Don't let anyone claim otherwise.

---

## 1. The Task

Two rounds. Both scored; classic is the headline, variant is the tiebreaker / contamination check.

### Round A — Classic 1BRC
- Input: `measurements.txt`, 1,000,000,000 lines of `Station;temp` (temp = one decimal, e.g. `-12.3`).
- Output: `{station=min/mean/max; ...}` sorted by station, mean rounded to 1 decimal, exact string match against reference (original 1BRC output spec).
- **Station names are NOT the official list.** Generated fresh: random-length (4–100 bytes) UTF-8-ish names from a synthetic alphabet, held-out seed. Defeats hardcoded hash tables tuned to the famous 413 keys.

### Round B — Variant (anti-retrieval)
- Same input file, different aggregation, announced only when the agent session starts. Example: per-station **median** and **standard deviation** (rounded per spec), or top-10 most frequent temperature values per station.
- This round forces actual implementation work — the exact solutions aren't sitting in a GitHub repo.
- Round B result breaks ties on the leaderboard and gets its own column.

## 2. Environment

**One dedicated box, sequential runs.** No fleet of "same-spec" VPSes — noisy neighbors make them not identical. Fairness comes from same silicon + same image + median-of-N scoring.

- Reference box (v1): dedicated Hetzner, e.g. Ryzen 9 7950X3D / EPYC, 64–128 GB RAM, 2× NVMe. ~€100–150/mo.
- **Immutable pinned image**: Linux (one distro, one kernel), snapshot taken before run 1, reused for every run. Everything reproducible: image hash published.
- Toolchains preinstalled on the image (no network during runs): gcc, clang, rust, go, graalvm+java, zig, plus python/node for glue. Vendored crate/pip caches optional in v2 — v1 is offline-strict.
- **Dev dataset:** 10M rows (same generator, different seed) — agent iterates against this.
- **Scored dataset:** 1B rows, held-out seed, generated by the judge right before each scored run.

## 3. Sandbox & Harness

Stolen directly from Prime Intellect's harness, adapted to CPU:

- Agent runs headless in a sandbox (bwrap + network namespace). Sees only its workdir, the datasets, the toolchains.
- **The only network route is a logging proxy that whitelists the model API and nothing else.** No web, no GitHub, no package registries in v1.
- Harness for v1: **one fixed agent framework, one fixed prompt** (e.g. claude-code-style CLI loop or a minimal custom loop). Models vary; nothing else does. V2 can add a "native CLI" track.
- Launch protocol (PI-style): repo + `program.md` + ONE message:
  > Read program.md and follow it exactly. Run fully autonomously — never stop, never ask for input. Goal: produce the fastest correct solution for the task in program.md within your budgets.
- Re-inject the goal message if the agent stalls/goes interactive.

## 4. Budgets

- **Wall clock: 4h agent time** (dev + build + iteration), then hard stop.
- **Token/cost cap:** fixed per run (e.g. $40 or 10M tokens), logged by the proxy. Hitting either cap = session ends, best validated submission stands.
- Agent submits an entry: `run.sh` (build + execute). Build/warmup phase untimed; only processing is timed (original 1BRC semantics).

## 5. Scoring & Verification

- **Frozen verifier, judge-side only.** Agent never touches seeds, reference output, or the scoring box state. `verify.py` and the generator are pinned in the public repo *before* run 1.
- Correctness gate: exact string match on the held-out dataset (round A) / exact match per spec (round B). Wrong output = DQ for that round, no partial credit.
- Timing protocol (judge-run, not agent-run): warmup pass, then 5 scored executions, **median** reported. Runs happen on the same box, sequential, thermals logged.
- **Per model: ≥3 independent agent sessions** (different session seeds). Leaderboard = best validated session (PI convention); median-of-sessions shown as the consistency metric.
- Reported per model: median runtime (headline), time-to-first-correct, total tokens, total $ cost, rounds passed.

## 6. Anti-cheat

- Output mismatch → DQ. Sandbox escape, verifier tampering, dataset modification, network probing → DQ + public log.
- Fresh station names + variant round neutralize memorized-solution hardcoding.
- No internet in v1 — contamination is already in the weights; live lookup at least gets stopped.
- Full proxy logs + shell history + traces published → the community audits everything.

### The planted test
`program.md` gives the agents a suggested timing protocol ("run it 3 times and take your best time"). This is deliberately suboptimal: best-of-3 is noisy and gameable; the right move is measuring timing variance themselves (page cache state, frequency scaling, CPU pinning) and building a proper protocol. Log which agents measure the box themselves vs trust the doc. Expect the self-measurers to cluster at the top, like PI's noise-estimation test (62/100 measured, 42 found the hidden trick, all top-of-table).

## 7. Publishing

Everything public from day one, in one repo:
- Harness, sandbox config, pinned image recipe, generator, frozen verifier
- Full traces + scratchpads + proxy logs + token/cost ledger per run
- Leaderboard site (static page is fine)

## 8. Roadmap

**v0.5 (actual v1, ~$0 extra):** Oussama's own PC + Docker, one session per model:
- Rows scaled down: 10M dev / 100M scored (~1.3GB file) — difficulty survives, cost doesn't
- Harness runs OUTSIDE the sandbox, calls the API, pipes agent commands into `docker exec` on a `--network none` container → agent needs zero internet, no proxy needed
- Models: GLM coding plan (sacrifice one 5h window), Codex weekly quota (one GPT session), DeepSeek API (~$2–3), OpenRouter $5 (one open model)
- Caps: 1–2h, n=1 per model — label everything "single-box, single-session, unofficial"
- Publish: harness + Dockerfile + datasets + traces. That artifact IS the sponsorship pitch for v1.

**v1 (sponsored, after v0.5 is public):** one dedicated box, 4–6 frontier models, 3 sessions each, 4h caps. Publish results + traces. Ping Gunnar Morling for blessing/boost — that's the reach.

**v2 (sponsored):** after v1 is public — labs for eval tokens (they care; both Anthropic & OpenAI run internal versions of this eval class per their system cards), compute sponsor for a beefier box / GPU round (e.g. a GPU aggregation task as round C), native-CLI track per model, community submissions.

## 9. Open questions

- Exact box spec (NVMe read speed vs RAM-only: 13GB fits in RAM — do we make the file page-cache-resident or cold? Pick one, publish it).
- Include `perf`/`flamegraph` tooling on the image or make agents roll their own?
- Round B variant: median+stdev vs frequency histogram — pick whichever has least prior art lying around.
- Should timing include first-touch page faults (cold cache) to punish mmap-lazy solutions or not? v1: warm cache, simple. Document it.
- Model list for v1 (4–6: e.g. Claude Opus 5, GPT-5.6, Gemini, Kimi K3, DeepSeek, GLM — whoever has API access).
